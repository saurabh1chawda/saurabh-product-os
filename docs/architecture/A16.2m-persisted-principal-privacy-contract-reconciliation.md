## Architecture Contract

Existing architecture distinguishes command provenance from authorization ownership:

- `PortfolioExecutionCommandContext.actorReference` is command audit metadata derived from the trusted presentation principal.
- The initialization `commandContext` is persisted as canonical aggregate state.
- `authorizationResourceReference` is the durable authorization ownership resource and is pseudonymous.
- Request/client-owned ownership and command-context-shaped fields are not trusted.

No reviewed architecture document forbids `actorReference` from persisting the approved trusted actor reference. A12.1 and A12.4 explicitly require preserving initialization command context exactly.

## Principal-to-Actor Mapping

`DefaultPortfolioWorkspaceActorReferenceMapper` maps a trusted principal into:

`principalType:authenticationProvider:principalId`

Tests assert this mapping for user and service principals. The value is an internal actor/audit reference, not an authorization ownership key and not a provider credential.

## Command Context Persistence

`PortfolioExecution` stores the initialization command context. The durable record mapper persists `commandContext` inside `aggregatePayload`, and mapper/repository tests assert deterministic round-trip of aggregate JSON.

Changing actor reference to a hash in this slice would alter approved Domain/Application audit semantics and would require a separate actor pseudonymization architecture decision.

## Authorization Resource Reference

`PortfolioWorkspaceProductionAuthorization` derives ownership from the trusted principal and hashes provider plus principal ID into:

`portfolio-workspace:principal:<principal-type>:<sha256>`

The request body, command context, actor reference, and transport headers cannot assert or override this ownership value.

## Security and Privacy Classification

| Concept | Persistence allowed? | Notes |
| --- | --- | --- |
| Authentication credential/token/session | No | Must not persist or appear in responses/errors. |
| Provider-specific user identity | Allowed only as internal actor audit reference under current contract | Public responses/errors must not expose it. |
| Internal actor/audit reference | Yes | `actorReference` persists with initialization command context. |
| Authorization ownership/resource reference | Yes, pseudonymous only | Must not contain raw provider/principal ID. |
| Public API response data | No raw principal/command context | Responses expose summaries and safe errors only. |
| Persistence-internal aggregate state | May contain command context | Repository records are not public presentation contracts. |
| Logs/errors | No sensitive internals | Safe serialization must redact credentials, SQL, stack/cause, revision, and resource internals. |

## Failure Classification

A. TEST ASSERTION DEFECT

The failing assertion conflated authorization ownership privacy with persisted command audit provenance. The test should verify that the authorization resource is hashed and spoofed ownership is ignored, not that no trusted actor reference exists anywhere in the persisted aggregate row.

## Correction

The live test now scopes raw principal/provider absence checks to `aggregate_payload.authorizationResourceReference` instead of the entire persisted row.

It still verifies:

- `authorizationResourceReference` matches the trusted principal-derived hash;
- the authorization resource is pseudonymous;
- spoofed ownership values are absent from the persisted row;
- public responses do not expose command context, facts, revision, or persistence internals.

## Regression Coverage
