# A16.2h - ATS Parsing Analyzer vs Resume Model Baseline Reconciliation

## 1. Executive Summary

A16.2h investigated the clean-baseline root build failure discovered after A16.2g:

`packages/ats-intelligence/src/analysis/ATSParsingAnalyzer.ts` expects `ResumeModel.artifact`, but committed `ResumeModel` does not expose `artifact`.

The broader committed consumer graph proves this is not only an ATS parsing issue. Committed ATS, Opportunity Intelligence, and Career Decision code all treat `ResumeModel` as a canonical artifact-bearing model. The selected classification is: MIXED BASELINE CONTRACT DEFECT, repaired by making Resume Intelligence produce and type a canonical `CareerArtifact`.

The repair was validated in an isolated clean simulation containing only:

- `HEAD`;
- staged `career-artifacts`;
- staged `explainability`;
- the Resume Intelligence artifact repair.

The clean simulation passed frozen install, relevant package validation, root build, root lint, root typecheck, and root test.

## 7. ResumeModel Consumer Assessment

Committed consumers of `ResumeModel` expect an artifact-bearing canonical model:

- ATS uses `resume.artifact` for source artifact IDs, parsing references, contact signals, and evidence references.
- Opportunity Intelligence uses `resume.artifact` for context references and fit/decision evidence references.
- Career Decision uses `resume.artifact.artifactId` when building decision context artifact references.

Adding `artifact` to `ResumeModel` is backward-compatible for existing fields, preserves existing `resumeId` and structured resume data, and aligns Resume Intelligence with the artifact model already used by adjacent intelligence packages.

## 8. ATS Analyzer Consumer Assessment

The ATS analyzer is not stale in isolation. Its tests and source already model ATS as a consumer of canonical Product/Career artifacts. The ATS fixture casts a ResumeModel with an `artifact` field, and the package boundary includes `@career-companion/career-artifacts`.

Changing ATS to avoid `resume.artifact` would leave Opportunity Intelligence and Career Decision broken and would undermine the shared artifact reference model.

## 9. Test Evidence

Committed Resume Intelligence tests previously did not assert an artifact.

The local repair adds regression coverage:

- `model.artifact.artifactType` is `Resume`;
- `model.artifact.sections` equals `model.sections`;
- the Resume package boundary includes `@career-companion/career-artifacts`.

Existing ATS tests pass when ResumeModel is repaired.

## 10. Candidate Repair Models

Model A - ResumeModel is missing artifact:

- Supported by committed ATS, Opportunity, and Career Decision consumers.
- Requires Resume Intelligence to depend on `career-artifacts`.
- Matches the local coherent repair candidate.

Model B - ATSParsingAnalyzer is stale:

- Rejected. ATS is not the only committed consumer expecting `ResumeModel.artifact`.

Model C - Missing adapter/mapping boundary:

- Rejected. Current package architecture passes canonical models directly between intelligence packages; no committed adapter boundary exists.

Model D - Mixed baseline defect:

- Selected. ATS introduced the artifact expectation after ResumeModel was introduced, while Resume Intelligence did not receive the corresponding contract update.

## 11. Selected Repair Model

Selected repair model: Model D, implemented by the Model A code shape.

Repair `ResumeModel` and `ResumeAnalyzer` so Resume Intelligence produces a canonical `CareerArtifact` and artifact-backed sections. This makes the committed consumer graph consistent without changing ATS, Opportunity, or Career Decision behavior.

## 12. Failure Classification

Classification: MIXED BASELINE CONTRACT DEFECT.

The baseline mismatch spans a producer contract and downstream consumers:

- consumers expect canonical artifact-bearing `ResumeModel`;
- producer did not type or construct that artifact.

## 13. Repair Applied

The repair uses the existing local Resume Intelligence hunks:

- add `@career-companion/career-artifacts` to `resume-intelligence`;
- add `artifact: CareerArtifact` to `ResumeModel`;
- make `ResumeSection` artifact-section compatible;
- construct the Resume `CareerArtifact` in `ResumeAnalyzer`;
- build artifact sections/blocks in `SectionBuilder`;
- add focused Resume Intelligence regression assertions.
