## 2. Purpose

This document normalizes Portfolio Workspace terminology before implementation continues.

It resolves naming ambiguity for the pilot bounded context. It does not redesign behavior, define lifecycle transitions, introduce implementation code, or authorize implementation beyond the canonical and clarified vocabulary listed here.

## 3. Normative Language

- MUST means required for Portfolio Workspace implementation.
- MUST NOT means prohibited unless a future accepted architecture decision supersedes this document.
- SHOULD means expected unless implementation evidence justifies an architecture review.
- MAY means permitted but not required.

`PortfolioExecutionCommandContext` is operation-specific when used by behavioral aggregate operations. Each fact-producing aggregate operation MUST receive one immutable command context, the returned fact MUST carry that exact context, and Application Results MUST derive `correlationId` from the returned fact. The `PortfolioExecution.commandContext` property represents the execution initialization context when persisted on the aggregate; it MUST NOT be substituted for later operation context.

| Term | Status | Decision |
| --- | --- | --- |
| PortfolioExecutionOutcome | DEFERRED | The concept is supported by ARCH-004 and the Portfolio Workspace README as terminal outcome vocabulary, but exact values are not defined in repository architecture documents. Do not implement until exact values are accepted. |

`PortfolioExecutionOutcome` remains distinct from `PortfolioExecutionLifecycle`. Lifecycle state does not imply outcome value.

## 13. Error Vocabulary Boundary

The next slice may define the Portfolio Workspace domain error catalog.

Error vocabulary rules:

- Identifier construction errors remain validation errors for scalar value objects.
- Domain errors represent rejected domain commands or invariant violations.
- Lifecycle transition errors belong to the domain catalog only when transition behavior is implemented.
- Duplicate identity errors belong to aggregate behavior, not scalar identifiers.
- Completion errors belong to work-item or execution completion behavior.
- Application authorization failures must remain outside the domain catalog.
- Infrastructure, persistence, transport, UI, and AI-provider failures must not enter the domain catalog.

Stable before A10.2.2.5:

- Aggregate name.
- Entity names.
- Identifier names.
- Reference and context names.
- Lifecycle concept names and implemented lifecycle values.
- Deferred status of `PortfolioExecutionOutcome`.
