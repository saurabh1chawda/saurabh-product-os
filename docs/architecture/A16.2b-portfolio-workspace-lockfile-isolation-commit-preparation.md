## 3. Mixed Lockfile Root Cause

The repository uses workspace globs:

```yaml
packages:
  - "apps/*"
  - "packages/*"
```

Because unrelated untracked packages currently exist under `packages/*`, pnpm records them as workspace importers when the lockfile is generated in the dirty primary worktree.

The current `pnpm-lock.yaml` therefore contains:

- required Portfolio Workspace importers and dependency resolutions;
- required `expect-type: 1.3.0` override resolution;
- required Drizzle/PostgreSQL package resolutions;
- required API test-only `pg` and `@types/pg` entries;
- unrelated `career-artifacts` and `explainability` workspace importers;
- unrelated `resume-intelligence` dependency changes;
- unrelated workspace links from other non-Portfolio packages to `career-artifacts` and `explainability`.

This is not a safe hand-editing situation. Several unrelated entries are importer-level workspace graph changes rather than a single adjacent dependency hunk.

   - `packages/career-artifacts/**`;

   - unrelated `packages/resume-intelligence/**` edits;
   - unrelated tests;
   - `e-2-complete`;


7. Use the temporary lockfile as the candidate replacement only after confirming it contains the required entries in section 6 and omits the unrelated entries in section 7.
