## Purpose

A16.3m introduces the narrow concrete executable HTTP host boundary for the
Portfolio Workspace public read API.

The host composes:

```text
PortfolioWorkspaceApiHost
  -> NodeHttpApiServer
  -> health endpoints
  -> public GET Portfolio Execution route
```

It does not expose public mutation, provider-specific authentication,
idempotency, repositories, persistence internals, or deployment startup.

## Executable Host Responsibility

`PortfolioWorkspaceExecutableHttpHost` owns:

- startup validation for listen host/port;
- construction of one existing `PortfolioWorkspaceApiHost`;
- construction of one `NodeHttpApiServer`;
- registration of health routes and the public GET route;
- listen/start lifecycle;
- deterministic shutdown of HTTP server followed by API host/runtime disposal;
- safe status metadata.

It does not own:

- Domain or Application behavior;
- repositories, Pool, Drizzle, schema, mapper, or migrations directly;
- authorization policy implementation;
- provider authentication or JWT parsing;
- durable idempotency;
- process signal handling;
- retry loops or orchestration frameworks.

## Configuration Boundary

The executable host receives explicit validated inputs:

- `apiHostEnvironment`;
- `listen.port`;
- optional `listen.host`;
- `trustedPrincipalResolver`.

The reusable executable host does not read `process.env`. Environment parsing
remains at a later outer deployment/bootstrap boundary.

Invalid port/host values fail before API host/runtime construction.

## Trusted Principal Dependency

There is no permissive production default.

The executable host requires a `PortfolioWorkspaceTrustedPrincipalResolver` for
public protected routes. A16.3m does not parse arbitrary identity headers,
bearer tokens, cookies, sessions, or provider claims.

Future deployment code must supply a trusted resolver backed by the approved
authentication boundary/provider integration.

## Route Registration

Registered public route:

```text
GET /v1/portfolio-workspace/executions/:executionId
```

The executable host reuses the A16.3l route factory. It does not duplicate route
matching, execution ID decoding, correlation handling, or internal Get handler
mapping.

## Liveness

Registered:

```text
GET /health/live
```

Success response:

```json
{ "status": "live" }
```

The endpoint reflects the API host liveness and returns no database URL, Pool,
Drizzle, repository, migration, schema, stack, or credential details.

## Readiness

Registered:

```text
GET /health/ready
```

Success response:

```json
{ "status": "ready" }
```

Not-ready response:

```json
{ "status": "not-ready" }
```

Readiness delegates to existing `PortfolioWorkspaceApiHost` readiness semantics.
No direct PostgreSQL probe was added.

## Startup Flow

Startup sequence:

```text
validate listen configuration
  -> require trusted principal resolver
  -> create PortfolioWorkspaceApiHost
  -> require API host readiness
  -> create route handler
  -> create NodeHttpApiServer
  -> bind/listen
  -> return PortfolioWorkspaceExecutableHttpHost
```

If HTTP start fails after API host creation, the host attempts to stop HTTP
resources and disposes the API host/runtime before returning failure.

## Running Host Contract

The running host exposes:

- `isLive()`;
- `isReady()`;
- `port()`;
- `status()`;
- `dispose()`;
- safe `toJSON()`.

It does not expose runtime, repository, Pool, Drizzle database, schema,
migration internals, or raw Node server.

## Shutdown

Shutdown order:

```text
NodeHttpApiServer.stop()
  -> PortfolioWorkspaceApiHost.dispose()
```

Repeated disposal is safe. Concurrent disposal shares one disposal operation.
Runtime is not disposed per request.

## Signal Decision

A16.3m does not register `SIGINT` or `SIGTERM`.

Signal ownership remains deferred to a final executable/deployment entrypoint so
the reusable host module stays testable and side-effect free.

## Error Contract

Added safe executable-host errors:

- `PortfolioWorkspaceExecutableHttpHostStartupError`;
- `PortfolioWorkspaceExecutableHttpHostShutdownError`.

Failure categories include invalid listen configuration, missing trusted
resolver, API host construction failure, API host not ready, HTTP start failure,
startup cleanup failure, HTTP stop failure, and API host disposal failure.

Errors expose safe names/codes only and do not include credentials, SQL,
database URLs, Pool, Drizzle, stack traces, or raw OS details in HTTP responses.

## Live PostgreSQL Test Architecture

A16.3m adds a dedicated live suite:

```text
pnpm --filter @career-companion/api test:integration:portfolio-workspace-http-host
```

The suite:

1. validates PostgreSQL 17;
2. creates a temporary schema in a test database;
3. seeds an execution through the approved internal API host initialization
   path;
4. starts the concrete executable HTTP host;
5. issues real loopback HTTP requests to health and public GET;
6. verifies persisted read behavior;
7. disposes and recreates the concrete host;
8. verifies the persisted execution is still readable;
9. confirms public mutation remains unavailable.

The suite is skipped during default database-free test runs and is explicitly
gated by `PORTFOLIO_WORKSPACE_TEST_DATABASE_URL`.

## CI Gate Decision

The concrete HTTP host is now part of the production release surface. The
existing A16.2 PostgreSQL 17 GitHub Actions job should run the new explicit live
HTTP-host command in addition to repository, idempotency, runtime, and API-host
integration suites.

## Public Mutation Guardrail

A16.3m does not expose:

```text
POST /v1/portfolio-workspace/executions
```

or any other public mutation route.

Public mutation remains blocked until durable idempotency and full production
authentication/authorization route semantics are approved.
