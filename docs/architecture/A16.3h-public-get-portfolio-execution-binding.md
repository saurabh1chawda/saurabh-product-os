# A16.3h - Public Get Portfolio Execution by ID Binding

- Status: Ready for A16.3i

- Scope: Framework-neutral authenticated public Get Portfolio Execution by ID binding

## Purpose

A16.3h implements the first authenticated public Portfolio Workspace operation:

```text
GET Portfolio Execution by ID
```

The implementation remains framework-neutral. It does not register an HTTP
route, choose Express/Fastify/Next.js routing, create a server, expose public
initialize, implement mutation idempotency, or call repositories directly.

## Placement

Implementation lives under:

```text
apps/api/src/portfolio-workspace/public/
```

Added public GET module:

```text
get-portfolio-execution.ts
```

This keeps public transport binding in the API package and outside Domain,
Application, Infrastructure, persistence, and runtime construction.

## Public Request

`GetPortfolioExecutionPublicRequest` contains only:

- primitive `executionId`;
- framework-neutral public headers;
- optional incoming correlation hint.

It does not accept principal, actor reference, command context, command ID,
authorization decision, repository revision, runtime, Application input, Domain
identifier object, session, cookie, token body field, or query token.

## Authentication Flow

The binding invokes `PortfolioWorkspacePublicAuthenticationBoundary` first:

```text
public request
  -> safe correlation normalization/generation
  -> strict Authorization bearer extraction
  -> authentication adapter
  -> trusted PortfolioWorkspacePresentationPrincipal
```

Authentication failure short-circuits before authorization, internal handler
execution, runtime service invocation, or Application behavior.

## Trusted Principal Flow

On success, only the trusted `PortfolioWorkspacePresentationPrincipal` crosses
into the existing internal get handler. Raw bearer token, Authorization header,
JWT claims, JOSE header, JWKS data, provider objects, and authentication errors
do not cross the boundary.

## Authorization Reuse

The binding reuses the existing `GetPortfolioExecutionInternalHandler`. That
handler already performs:

- runtime readiness check;
- presentation request construction;
- Get input mapping;
- host authorization through `PortfolioWorkspaceInternalAuthorization`;
- runtime `getPortfolioExecution` invocation;
- safe presentation response/error mapping.

A16.3h does not implement a new authorization policy and does not duplicate
authorization logic.

## Get Mapping

The public binding passes primitive `executionId` into the internal handler path.
The existing presentation mapper remains responsible for converting it to
Application input and producing safe invalid-identifier failures.

The public layer does not construct `ExecutionId` directly.

## Correlation

The public authentication boundary creates the single safe correlation identity
for the request. The public GET binding passes that correlation into the
internal handler through the existing correlation header contract.

The response maps the internal correlation header back to the public
`x-correlation-id` header. Unsafe incoming correlation is not echoed.

## Success Contract

Success returns `GetPortfolioExecutionPublicResponse` with:

- status `200`;
- existing versioned Get presentation response body;
- safe correlation header.

The response does not expose:

- Domain aggregate;
- Domain facts;
- command context;
- repository revision;
- persistence metadata;
- runtime state;
- raw credential;
- provider identity object;
- authorization internals.

## Failure / Status Behavior

Public failure behavior follows existing safe mappings:

| Failure | Status | Challenge |
| --- | ---: | --- |
| missing/malformed/invalid bearer credential | 401 | `WWW-Authenticate: Bearer` |
| authentication/verifier unavailable | 503 | none |
| invalid authentication configuration | 500 | none |
| invalid execution ID | 400 | none |
| authorization denied | 403 | none |
| execution not found | 404 | none |
| persistence unavailable | 503 | none |
| internal failure | 500 | none |

Nested causes, stacks, SQL, database metadata, JWKS/provider details, and token
material are not exposed.

## Privacy / Security

Tests prove the public GET response and error objects do not expose raw bearer
tokens, Authorization headers, JWT/JWKS details, provider internals, password,
SQL, stack, cause, revision, command context, aggregate, runtime, or principal
objects.

Public GET authenticates identity first but still requires authorization before
runtime query execution.

## Host Composition Decision

The binding is constructed independently from host-owned dependencies. It
depends on:

- `PortfolioWorkspacePublicAuthenticationBoundary`;
- `GetPortfolioExecutionInternalHandler`.

`PortfolioWorkspaceApiHost` was not changed. This avoids expanding host
lifecycle/disposal behavior and keeps the route-binding object explicit for a
future concrete framework adapter.

## Public Initialize / Idempotency Absence

A16.3h does not implement public initialize, public mutation, durable
idempotency route binding, command context creation, mutation authorization, or
retry behavior. Public initialize remains blocked until those controls are
approved and validated.

## Remaining Blockers

Remaining for A16.3i and later:

- concrete framework/HTTP route binding;
- deployed provider/JWKS configuration validation;
- public route live validation;
- public forbidden-versus-not-found concealment decision if required;
- rate limiting and abuse controls;
- observability/logging policy;
- public mutation/idempotency route binding.

## Final Decision

READY FOR A16.3i.

A16.3h provides the first authenticated public operation binding while
preserving the existing internal authorization/runtime path and keeping public
initialize unavailable.
