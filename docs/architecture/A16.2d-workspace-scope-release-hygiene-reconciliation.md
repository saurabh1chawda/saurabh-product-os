## 2. Executive Summary

A16.2d supersedes the earlier assumption that `career-artifacts` and `explainability` importer entries can simply be removed from the Portfolio Workspace release lockfile.

Forward reference: A16.2e performs the missing-package baseline repair decision and classifies the current untracked `career-artifacts` and `explainability` packages as the recommended shared workspace baseline repair, pending approval.

The evidence shows a deeper release-hygiene issue:

- `packages/career-artifacts` does not exist in `HEAD`.
- `packages/explainability` does not exist in `HEAD`.
- `packages/resume-intelligence` exists in `HEAD`.
- Many committed package manifests in `HEAD` already depend on `@career-companion/career-artifacts` and/or `@career-companion/explainability`.
- `HEAD:pnpm-lock.yaml` already contains `packages/career-artifacts:` and `packages/explainability:` importers.

Therefore, these package importers are not purely accidental A16 local noise. The committed baseline already expects those workspace packages, but their package source directories are not committed.

The selected release model is Model C: release cannot be isolated safely yet.

Before A16.2 can proceed to staging approval, the repository needs an explicit release-scope decision:

1. include `career-artifacts` and `explainability` as required shared workspace baseline-repair packages; or
2. narrow root CI / workspace validation scope in an architecture-approved way; or
3. correct the committed non-Portfolio manifests so they no longer require missing workspace packages.
