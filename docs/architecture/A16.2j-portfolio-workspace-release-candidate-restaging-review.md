## Infrastructure Type Failure Root Cause

The failed typecheck was in:

```text
packages/infrastructure/src/portfolio-workspace/runtime/PortfolioWorkspaceMigrationReadiness.ts
```

Two type boundaries met there:

- `Result<T, E>` stores `value` as optional at the type level, even after a successful result.
- Drizzle `MigrationConfig.migrationsTable` is typed as optional.

The previous implementation derived migration configuration with a fallback:

```text
activeSchema.value ?? "public"
```

and later passed:

```text
migrationConfig.migrationsTable
```

to a helper requiring a concrete `string`.

That produced the TypeScript error and also made the schema-derived metadata contract less strict than A16.1 intended. If PostgreSQL cannot report an active schema, readiness should fail safely rather than silently using `public`.

## Failure Classification

Classification: Infrastructure production type and readiness contract defect.

The defect was not Domain or Application behavior. It was not a migration artifact defect, repository contract defect, API defect, lockfile defect, or CI workflow defect.

## Correction Applied

The readiness flow now requires `readCurrentSchema(...)` to succeed and expose a concrete value before deriving migration metadata.

The code now:

- treats missing active schema as `database-unavailable`;
- derives `migrationMetadataTable` from the concrete active schema;
- passes that concrete table name to both Drizzle migration configuration and applied-migration inspection;
- preserves `drizzle` as the metadata schema;
- preserves `__portfolio_workspace_migrations_<hash>` as the metadata table prefix;
- avoids fallback, cast, and non-null assertion shortcuts.

## Regression Test

Added a focused migration-readiness regression test:

```text
requires PostgreSQL to resolve an active schema before deriving migration metadata
```

The test proves that when the schema probe returns no usable `current_schema`, readiness fails as `database-unavailable`, migration application is not invoked, and metadata identity is not derived from a stale or fallback schema.

## Migration Metadata Verification

The final migration metadata design remains:

```text
schema: drizzle
table: __portfolio_workspace_migrations_<16-character sha256 schema hash>
```

The table name is derived from the active schema returned by:

```sql
select current_schema() as current_schema
```

This prevents cross-schema collisions in PostgreSQL live tests and keeps the metadata table short enough for PostgreSQL identifier limits.
