## Purpose

A16.5a implements the database-free contracts needed by later durable mutation idempotency work. It does not implement persistence, transactions, handler integration, public routes, retries, cleanup, telemetry, or PostgreSQL migrations.

## Package Placement

Contracts live in:

`apps/api/src/portfolio-workspace/idempotency/`

Rationale:

- the public idempotency key is presentation/transport-adjacent;
- replay payloads are safe presentation response payloads;
- Domain must not know about idempotency;
- Application mutation inputs/results are not redesigned for retry semantics;
- Infrastructure durable storage will be introduced later under Infrastructure.

## Key Contract

`PortfolioWorkspaceIdempotencyKey` is an immutable opaque value.

Rules:

- constructed through `Result`;
- trims surrounding whitespace;
- non-empty;
- maximum length 128 characters;
- safe characters: letters, digits, `.`, `_`, `:`, `-`;
- no control characters or spaces after normalization;
- deterministic `equals()` and `toJSON()`;
- no semantic interpretation.

The key is not a command ID, correlation ID, authentication token, principal ID, or Domain identifier.

## Operation Vocabulary

`PortfolioWorkspaceIdempotencyOperation` defines the nine mutation operations:

- `initialize-execution`
- `begin-execution`
- `activate-work-item`
- `complete-work-item`
- `cancel-work-item`
- `accept-candidate`
- `reject-candidate`
- `complete-execution`
- `cancel-execution`

The vocabulary is presentation/idempotency-owned and does not reuse Domain fact names.

## Scope Contract

`PortfolioWorkspaceIdempotencyScope` contains:

- operation;
- `PortfolioWorkspaceAuthorizationResourceReference`;
- primary resource identity;
- idempotency key.

It excludes:

- actor reference;
- raw provider principal ID;
- email;
- session/JWT/auth claims;
- command ID;
- correlation ID.

The scope uses the A16.4/A16.2m pseudonymous authorization resource model.

## Fingerprint Contract

`PortfolioWorkspaceIdempotencyFingerprintInput` contains:

- scope;
- presentation version;
- deterministic request intent.

`PortfolioWorkspaceIdempotencyFingerprint` stores:

- algorithm: `sha256`;
- lowercase hex digest.

Calculation uses Node's built-in `node:crypto` and canonical JSON with sorted object keys. Arrays preserve order so initialization work item and candidate ordering remains explicit rather than silently canonicalized away.

Fingerprint input excludes correlation IDs, command IDs, occurredAt, actor reference, volatile headers, auth tokens, sessions, and current clock.

## Initialize Example

`createInitializePortfolioExecutionFingerprintInput()` demonstrates initialization fingerprint input from:

- operation and scope;
- execution ID;
- portfolio plan reference;
- plan snapshot reference;
- approval reference;
- initial work items;
- initial candidates.

Changing meaningful intent changes the fingerprint. Changing correlation, command ID, time, or actor reference does not.

## Replay Payload

`PortfolioWorkspaceIdempotencyReplayPayload` is immutable and presentation-safe.

It contains:

- presentation version;
- presentation outcome;
- original successful correlation ID;
- success status;
- approved response body JSON;
- safe replay headers.

It does not contain Domain facts, command context, actor reference, aggregate state, revision, repository rows, SQL metadata, stack/cause, auth tokens, sessions, or raw provider objects.

## Correlation Replay Policy

Replay payloads preserve the original successful result correlation. A retry can have a host-local correlation for diagnostics, but it must not mutate the persisted replay result.

## Outcome Vocabulary

`PortfolioWorkspaceIdempotencyOutcomeKind` defines transport-neutral coordination outcomes:

- `first-execution-reserved`
- `replay-succeeded`
- `conflict-fingerprint-mismatch`
- `in-progress`
- `storage-unavailable`
- `released-after-failure`
- `expired-new-reservation`

These are not HTTP status codes. Presentation will map them later.

## Error Contract

`PortfolioWorkspaceIdempotencyContractError` exposes safe reasons:

- `invalid-idempotency-key`
- `invalid-idempotency-scope`
- `invalid-fingerprint-input`
- `fingerprint-mismatch`
- `idempotency-in-progress`
- `replay-payload-invalid`
- `storage-unavailable`
- `internal-idempotency-contract-failure`

Errors serialize only name, code, and reason.

## Privacy Guarantees

The contracts store no credentials, provider tokens, sessions, cookies, JWT claims, email addresses, stack traces, SQL, SQLSTATE, Drizzle rows, PostgreSQL rows, or aggregate JSON. Pseudonymous `authorizationResourceReference` is the only authorization identity dimension.
