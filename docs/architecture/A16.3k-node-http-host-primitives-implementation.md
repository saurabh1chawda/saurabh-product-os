# A16.3k - Node HTTP Host Primitives Implementation

- Status: Ready for A16.3l
- Date: 2026-08-16

- Scope: Generic Node HTTP server primitives and transport contracts for `apps/api`

## Purpose

A16.3k implements the concrete transport shell selected by A16.3j:

```text
apps/api standalone Node built-in HTTP host
```

This slice creates only generic HTTP primitives. It does not implement the
Portfolio Workspace public Get route, public Initialize, authentication provider
logic, authorization policy, idempotency, health endpoints, OpenAPI, telemetry,
or deployment configuration.

## Package Placement

Implementation lives under:

```text
apps/api/src/http/
```

This keeps the HTTP layer outside Portfolio Workspace Domain, Application,
Infrastructure, presentation, internal handlers, and runtime host composition.

## Transport Contracts

A16.3k adds:

- `NodeHttpRequest`
- `NodeHttpResponse`
- `NodeHttpRequestHandler`
- `NodeHttpHeaders`
- `NodeHttpApiServerListenOptions`
- `NodeHttpApiServerStatus`
- `NodeHttpApiServer`

The request contract exposes only:

- method;
- pathname;
- raw search string;
- normalized headers.

It does not expose `IncomingMessage`, sockets, `ServerResponse`, streams,
runtime objects, repositories, Application Services, or Domain objects.

## Header Normalization

The Node host normalizes incoming headers to lower-case keys and preserves
string or multi-value header values. Header values are bounded before reaching
the injected handler.

The HTTP host does not interpret `Authorization`, does not authenticate, and
does not normalize correlation semantics. Those remain owned by the public
Portfolio Workspace authentication/binding layer.

## URL / Path Parsing

The host uses Node-standard `URL` parsing with a local base. It exposes
`pathname` and `search` separately.

It does not route, decode Portfolio Workspace path parameters, parse
`executionId`, or bind any Portfolio Workspace endpoint.

## Request Body Policy

A16.3k does not collect or parse request bodies.

The first approved public route is a read-only GET, and public mutations remain
blocked. Route-owned body handling can be added later when a concrete mutation
route is approved.

## Response Model

`NodeHttpResponse` contains:

- numeric status;
- explicit headers;
- optional JSON body.

The server writes deterministic JSON responses using
`content-type: application/json; charset=utf-8`.

It does not serialize Domain/Application objects, raw errors, stacks, causes,
repositories, runtime state, database metadata, tokens, or provider claims.

## Error Containment

Unexpected handler failures are contained and returned as a generic safe 500:

```json
{
  "error": {
    "code": "internal-error",
    "message": "Internal server error."
  }
}
```

Oversized or malformed transport input produces a safe generic 400.

## Server Lifecycle

`NodeHttpApiServer` owns:

- Node `http.Server` construction;
- `start(...)`;
- `stop()`;
- lifecycle state;
- safe status serialization.

Lifecycle values:

- `created`
- `starting`
- `listening`
- `stopping`
- `stopped`
- `failed`

Repeated stop is safe. Concurrent stop is safe. Double start while listening
returns the current status rather than creating another listener.

The server does not register process signals, call `process.exit`, create global
singletons, or create one server per request.

## Listen Configuration

The listen configuration accepts:

- `port`;
- optional `host`.

Port must be an integer from `0` through `65535`. Port `0` is allowed for tests.
Blank host values are rejected.

The primitive does not read `process.env`. Future executable/bootstrap code owns
environment mapping.

## Shutdown Semantics

`stop()` uses Node server close semantics to stop accepting new connections and
close the server.

Sophisticated in-flight draining remains deferred. Future executable host
composition should coordinate:

```text
HTTP server close
  -> PortfolioWorkspaceApiHost.dispose()
```

`PortfolioWorkspaceApiHost` is not composed in this generic HTTP primitive.

## Safe Status

Server status exposes only:

- lifecycle;
- listening boolean;
- bound host, if available;
- bound port, if available.

It does not expose sockets, credentials, environment, handler internals, runtime
objects, repositories, or database details.

## Tests

Database-free tests cover:

- ephemeral loopback startup;
- safe status serialization;
- method/path/search/header normalization;
- real HTTP response serialization;
- safe 500 on unexpected handler rejection;
- safe 400 on oversized headers;
- Authorization and correlation transport without interpretation;
- repeated and concurrent stop;
- listen validation;
- source-boundary purity.

## Public Exports

The API root now explicitly exports the generic HTTP primitives needed by future
host composition.

It does not export raw Node `Server`, sockets, `IncomingMessage`,
`ServerResponse`, or test seams.

## Executable Entrypoint Decision

No executable `main.ts` or long-running server process was added.

A16.3k provides reusable primitives only. A16.3l should bind the public Get route
adapter. A later slice can add executable startup once routes and host
composition are ready.

## A16.3l Reconciliation

A16.3l now binds the first Portfolio Workspace public read-only route using the
A16.3k primitive:

```text
GET /v1/portfolio-workspace/executions/:executionId
```

The generic HTTP primitive remains framework-neutral and route-agnostic. The
Portfolio Workspace route lives separately under
`apps/api/src/portfolio-workspace/http`, preserving the split between transport
shell and bounded-context route adaptation.

## A16.3m Reconciliation

A16.3m uses the generic `NodeHttpApiServer` inside
`PortfolioWorkspaceExecutableHttpHost`. The primitive still owns only Node HTTP
request normalization, JSON response serialization, and server start/stop
lifecycle. Health/readiness behavior and Portfolio Workspace route registration
are owned by the executable Portfolio Workspace HTTP host layer, not by the
generic primitive.
