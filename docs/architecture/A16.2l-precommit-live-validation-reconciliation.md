## appliedMigrationCount Assessment

The API host live test had stale hard-coded assertions expecting `appliedMigrationCount()` to be `1`. With the current committed migration inventory, the correct applied migration count is the number of entries in the Drizzle migration journal: `2`.

Repository and runtime live suites already demonstrated that the two-migration state is valid. The API host failure was therefore test-contract drift.

## API Host Failure Root Cause

The API host live test asserted a fixed migration count from the earlier one-migration schema state. Once idempotency introduced the second migration, the hard-coded `1` no longer represented the authoritative migration inventory.

## API Host Failure Classification

Classification: TEST CONTRACT DRIFT.

No production host, runtime, repository, schema, or migration behavior was implicated.

## Migration Assertion Decision

The assertion now derives the expected count from the committed Drizzle journal rather than replacing the stale value with another hard-coded constant. This preserves the architectural check while allowing the test to track the reviewed migration inventory.

## Idempotency Runner Investigation

The idempotency integration runner failed before executing tests because Node 22 native strip-types execution could not resolve an extensionless relative import of the shared PostgreSQL test harness.

The other live integration runners avoid this failure mode by keeping the database safety assertion local to the runner.

## Idempotency Module Resolution Root Cause

Root cause: TEST HARNESS MODULE RESOLUTION DEFECT.

The idempotency runner imported `./portfolio-workspace-postgres-test-harness` without an emitted JavaScript extension in a native TypeScript execution path. TypeScript compilation disallowed a `.ts` suffix without `allowImportingTsExtensions`, so the stable correction was to inline the small runner-local safety guard.

## Idempotency Scope Classification

The idempotency live suite belongs to the later A16.5 durable idempotency scope. It is not part of the original A16.2k Portfolio Workspace release-candidate scope unless that scope is explicitly expanded.

Because the current working tree includes the A16.5b migration, schema, store, and integration script, the runner correction is valid as a harness fix for that current tree. The final commit plan must decide whether idempotency artifacts are included in the next release-candidate commit or held for a later commit.
