## Purpose

A16.3l implements the first concrete public Portfolio Workspace HTTP route:

```text
GET /v1/portfolio-workspace/executions/:executionId
```

The route is read-only and database-free in this slice. It binds the generic
Node HTTP transport primitive from A16.3k to the existing Portfolio Workspace
internal Get handler path.

## Placement

Route implementation lives under:

```text
apps/api/src/portfolio-workspace/http/
```

This keeps concrete Portfolio Workspace route adaptation outside the generic
HTTP server, Domain, Application, Infrastructure, persistence, and runtime
composition.

## Route Contract

Supported route:

```text
GET /v1/portfolio-workspace/executions/:executionId
```

Rules:

- method must be `GET`;
- exactly one path segment must appear after `/executions/`;
- extra path segments return safe 404;
- blank or malformed encoded execution IDs return safe 400;
- query string does not affect route identity;
- unsupported method on the matching route returns 405 with `Allow: GET`.

No aliases, version negotiation, list route, or mutation route were added.

## Trusted Principal Boundary

A16.3l does not implement provider authentication. Instead, the route receives a
narrow injected `PortfolioWorkspaceTrustedPrincipalResolver`.

That resolver represents the host-authenticated trust boundary:

```text
HTTP request
  -> trusted principal resolver
  -> PortfolioWorkspacePresentationPrincipal
  -> internal Get handler
```

The route does not parse JWTs, sessions, OAuth tokens, cookies, API keys, or
Authorization headers into principals. It does not trust path, query, body, or
arbitrary header data as actor identity.

## Correlation Flow

The route reads the existing `x-correlation-id` header as an untrusted hint.

Flow:

```text
incoming x-correlation-id
  -> existing normalization/generation
  -> internal Get handler
  -> response x-correlation-id
```

Unsafe incoming values are replaced and are not echoed.

## Internal Handler Reuse

The route invokes `GetPortfolioExecutionInternalHandler`. It does not duplicate:

- presentation request mapping;
- Application input construction;
- runtime readiness checks;
- authorization;
- Application Service invocation;
- persistence failure mapping;
- response projection mapping.

## Status Behavior

The route supports:

| Condition | Status |
| --- | ---: |
| success | 200 |
| invalid path/execution ID | 400 |
| unauthenticated trusted-principal resolution | 401 |
| authorization denied | 403 |
| route not found / execution not found | 404 |
| wrong method on matching route | 405 |
| runtime or persistence unavailable | 503 |
| unexpected route failure | 500 |

HTTP status codes remain in the API transport boundary and are not moved into
Domain or Application.

## Response Contract

Success uses the existing v1 Get presentation response:

- `version`;
- `correlationId`;
- safe execution summary.

Responses do not expose:

- aggregate;
- Domain facts;
- command context;
- repository revision;
- PostgreSQL metadata;
- runtime object;
- service object;
- principal object;
- raw internal handler result.

## Header Policy

The generic Node HTTP server sets:

```text
content-type: application/json; charset=utf-8
```

The route returns:

- `x-correlation-id`;
- `allow: GET` only for 405.

No server internals, runtime lifecycle, database metadata, credentials, stack
traces, or provider details are returned.

## Route Matcher Decision

A16.3l implements a small explicit matcher. No Express, Fastify, Hono,
path-to-regexp, controller framework, reflection router, service locator, or DI
container was introduced.
