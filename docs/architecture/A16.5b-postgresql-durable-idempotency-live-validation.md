## Application Contract

The Application package owns transport-neutral idempotency contracts:

- Portfolio Workspace mutation operation vocabulary.
- SHA-256 idempotency key hash value.
- SHA-256 request fingerprint value.
- authorization-resource scoped identity.
- replay payload value.
- reservation and completion outcomes.
- technology-neutral idempotency port and errors.

The Application contract does not accept HTTP headers, raw idempotency keys, PostgreSQL rows, Drizzle objects, sessions, JWTs, or infrastructure clients.

## Uniqueness and Reservation

The primary lookup identity is `scope_hash`, derived from operation, authorization resource reference, resource identity, and idempotency key hash.

The table also has a unique index on:

```text
operation
authorization_resource_reference
resource_identity
idempotency_key_hash
```

Fingerprint is intentionally excluded from the uniqueness boundary. Same identity with a different request fingerprint is a conflict, not a second valid reservation.

## Store Semantics

`PostgresPortfolioWorkspaceIdempotencyStore.reserve()` uses an atomic PostgreSQL insert with conflict handling.

Expected outcomes:

- absent record: `first-execution-reserved`
- same key and same fingerprint while reserved: `in-progress`
- same key and same fingerprint after success: `replay-succeeded`
- same key and different fingerprint: `conflict-fingerprint-mismatch`

Successful completion updates only a matching reserved record with the same scope hash and fingerprint. Release deletes only a matching reserved record.

## Atomic Orchestration

`PostgresPortfolioWorkspaceIdempotentMutationOrchestrator` executes reservation, transaction-bound `PostgresPortfolioExecutionRepository` mutation work, and replay completion inside one Drizzle transaction.

On mutation failure or replay completion failure, the orchestrator returns the safe failure and rolls back the database transaction. Aggregate persistence and replay completion cannot commit independently through this orchestrator.
